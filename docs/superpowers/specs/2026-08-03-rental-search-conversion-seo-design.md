# Space DDF 대관 검색·전환 SEO 설계

## 목표

Space DDF의 기존 대관 신청 흐름을 유지하면서 `광주 전시공간 대관`, `광주 예술전시 대관`, `광주 워크숍 공간 대관` 검색 의도에 맞는 정보를 검색엔진과 방문자에게 명확히 제공한다. 검색 노출만 늘리는 것이 아니라 대관 가능 일정 확인과 신청 완료까지의 전환을 측정하고 개선할 수 있게 한다.

## 대상과 제외 범위

- 주요 대상: 개인 작가, 예술가 팀, 기획자, 문화예술 단체, 워크숍 운영자
- 허용 용도: 예술전시, 사진·영상·설치·사운드·출판·리서치 기반 프로젝트, 예술 워크숍
- 제외 키워드와 용도: 촬영 스튜디오, 상업 팝업, 파티, 일반 행사용 대관
- 검색 순위나 문의량을 보장하는 표현, 실제로 제공하지 않는 시설·서비스·가격 정보는 작성하지 않는다.

## 검색 랜딩 구조

기존 `/rental` 경로를 유일한 대관 랜딩으로 유지한다. 새 키워드별 얇은 페이지를 만들지 않는다. 페이지 상단은 다음 검색 의도를 즉시 충족한다.

1. H1에서 광주 전시공간 대관임을 명확히 밝힌다.
2. 예술전시와 워크숍을 포함한 허용 프로젝트 범위를 짧게 설명한다.
3. 공간 위치, 접수 절차, 지원사업 할인 검토 정보를 사실 그대로 표시한다.
4. 현재 대관 가능 일정과 신청서를 기존 기능으로 연결한다.
5. 하단 FAQ에서 용도, 신청 절차, 일정, 결제, 할인 관련 반복 질문에 답한다.

시각 스타일은 기존 Space DDF의 선, 여백, 타이포그래피 체계를 유지한다. SEO를 위해 과도한 문구 반복, 키워드 나열, 별도 마케팅 카드 그리드를 추가하지 않는다.

## 기술 SEO

### 네이버 소유 확인

기본 HTML의 공통 `<head>`에 아래 메타 태그를 정확히 한 번 넣는다.

```html
<meta name="naver-site-verification" content="db3ba905f8c30216f6a47a1d221582fdb5bef855" />
```

### `/rental` 전용 메타데이터

클라이언트 라우팅과 정적 프리렌더 결과가 같은 값을 사용한다.

- canonical: `https://spaceddf.xyz/rental`
- title: 광주 전시공간 대관과 Space DDF를 앞쪽에 배치한다.
- description: 광주 동구 위치, 예술전시·워크숍 범위, 가능 일정 확인과 온라인 신청을 자연스럽게 포함한다.
- Open Graph와 Twitter 메타데이터도 같은 메시지를 사용한다.
- robots는 기존의 확장 미리보기 허용 정책을 유지한다.

### 구조화 데이터

`/rental`에는 하나의 JSON-LD `@graph`로 다음 엔터티를 연결한다.

- `BreadcrumbList`: Space DDF → 대관 신청
- `Service`: 예술전시 및 워크숍 공간 대관 서비스, 제공자와 제공 지역 연결
- 기존 `ArtGallery`·`EventVenue`: 주소, 공식 URL, 연락처, Instagram 유지
- `FAQPage`: 화면에 실제 표시되는 FAQ와 동일한 질문과 답변만 포함

가격, 면적, 수용 인원처럼 확인되지 않은 속성은 구조화 데이터에도 넣지 않는다.

### 발견 가능성

- `public/sitemap.xml`에 `/rental`을 추가하고 변경 빈도는 weekly, 우선순위는 0.9로 설정한다.
- 홈의 대관 요약과 전시 상세의 문맥에 맞는 내부 링크가 `/rental`을 가리키게 한다.
- `/admin`은 검색 유입 대상이 아니며 기존 노출 정책을 변경하지 않는다.

## 전환 측정

기존 Google Analytics 로더를 확장하되 측정 ID가 설정된 운영 도메인에서만 동작하게 한다. 개인정보나 자유 입력값은 전송하지 않는다.

- `rental_view`: 대관 랜딩 진입
- `rental_date_select`: 유효한 일정 범위 선택
- `rental_form_start`: 첫 신청 필드 입력
- `rental_submit_success`: 서버 접수 성공
- `rental_submit_error`: 접수 실패, 오류 종류는 제한된 내부 코드만 사용

동일 페이지 체류 중 `rental_view`와 `rental_form_start`는 한 번만 기록한다. 이벤트 전송 실패가 신청 기능을 막아서는 안 된다.

## 데이터 흐름과 오류 처리

1. 빌드 시 `/rental/index.html`에 전용 메타데이터와 JSON-LD를 생성한다.
2. SPA 라우팅 시 `updateSeo`가 같은 canonical, 메타데이터, JSON-LD를 설정한다.
3. 대관 가능 일정 API 실패 시 기존 안내를 유지하며 SEO 안내 콘텐츠와 FAQ는 계속 표시한다.
4. 분석 라이브러리가 없거나 차단되어도 이벤트 함수는 조용히 종료한다.
5. 신청 성공과 실패의 기존 사용자 메시지는 유지하며 분석 이벤트만 부수 효과로 추가한다.

## 검증

- 네이버 소유확인 메타가 소스 HTML과 프리렌더 HTML에 존재하는지 검사한다.
- `/rental` canonical, title, description, OG, JSON-LD, 사이트맵을 자동 테스트한다.
- JSON-LD의 FAQ 내용과 화면 FAQ가 일치하는지 소스 계약 테스트를 둔다.
- 분석 이벤트가 운영 조건에서만 전송되고 자유 입력값을 포함하지 않는지 단위 테스트한다.
- 기존 대관 일정 선택과 신청 API 테스트를 회귀 실행한다.
- 모바일·데스크톱에서 H1, 안내, 달력, 신청서, FAQ의 순서와 가로 넘침을 브라우저로 확인한다.
- 프로덕션 빌드 후 `/rental/index.html`을 직접 검사하고 배포 URL 및 운영 URL의 HTTP 200을 확인한다.

## 완료 기준

- 네이버 사이트 소유확인 태그가 운영 HTML에서 확인된다.
- `/rental`이 홈이 아닌 자체 canonical과 검색 메타데이터를 갖는다.
- 검색 결과에서 이해할 수 있는 실제 대관 안내가 페이지에 표시된다.
- 구조화 데이터가 화면 정보와 일치하며 검증 가능한 속성만 포함한다.
- 대관 유입부터 신청 성공까지 익명 전환 이벤트를 측정할 수 있다.
- 전체 테스트, 린트, Pages 빌드 및 운영 스모크 검사가 통과한다.
