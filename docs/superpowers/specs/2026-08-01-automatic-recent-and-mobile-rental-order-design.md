# 자동 Recent 노출과 모바일 대관 순서 설계

## 목표

관리자가 `/admin`에서 콘텐츠를 공개하면 별도 노출 옵션 없이 선택한 유형의 홈 목록과 `Recent Updated`에 자동으로 반영한다. 모바일 홈에서는 Calendar 대관 영역을 콘텐츠 영역 아래 마지막 행에 배치한다.

## 관리자 편집 화면

- 기본 정보 섹션의 콘텐츠 유형을 `Show`와 `Project` 중 하나를 고르는 명확한 선택 컨트롤로 제공한다.
- 현재의 `메인 목록에 표시`와 `Recent Updated 대표 콘텐츠` 체크박스는 제거한다.
- 새 콘텐츠는 현재 필터가 Show 또는 Project이면 해당 유형으로 시작하고, 그 외에는 Show를 기본값으로 사용한다.
- 유형은 임시 저장 중 변경할 수 있으며, 공개 시점의 유형이 최종 목록과 상세 URL을 결정한다.

## 어드민 업로드·공개 프로세스

- 새 콘텐츠 생성, 기존 콘텐츠 수정, 복제 후 수정 모두 동일한 편집·공개 흐름을 사용한다.
- 텍스트와 유형 선택은 기존 자동 저장을 유지한다. 포스터, 목록 프리뷰, 갤러리 업로드가 끝난 뒤에도 최신 draft 상태를 유지한다.
- 이미지 업로드만으로 공개하지 않는다. 관리자가 Publish를 눌러 서버 검증을 통과한 시점에만 홈 목록과 Recent를 갱신한다.
- Publish 직전 자동 저장이 끝나지 않았다면 최신 draft를 먼저 저장한 다음 공개한다.
- Publish 성공 응답에는 최종 `type`, `showOnHome`, `isFeatured`, `publishedAt`을 포함하며 어드민 화면도 그 응답으로 즉시 갱신한다.
- 공개된 콘텐츠의 유형을 바꿔 다시 Publish하면 이전 유형의 공개 경로와 목록 항목은 제거되고 새 유형의 경로와 목록에만 나타난다.
- 업로드 또는 Publish가 실패하면 공개 상태를 바꾸지 않고, 실패 단계와 필드를 어드민 알림 및 검증 패널에 표시한다.

## 공개 규칙

- Publish 성공 시 서버가 콘텐츠의 `showOnHome`과 `isFeatured`를 항상 `true`로 저장한다.
- 기존 Recent 대표 콘텐츠의 `isFeatured`는 같은 트랜잭션에서 `false`로 변경한다.
- 공개 스냅샷의 `published_at`은 Publish가 성공한 시각으로 갱신한다. 이미 공개된 콘텐츠를 다시 Publish하면 그 콘텐츠가 최신 Recent가 된다.
- Show로 공개된 콘텐츠는 홈 Show 목록과 `/shows/:slug`에 노출한다.
- Project로 공개된 콘텐츠는 홈 Project 목록과 `/projects/:slug`에 노출한다.
- 비공개 또는 휴지통 이동 시 공개 목록과 Recent 대상에서 제외한다.

## 홈 데이터 흐름

- 앱 시작 시 Show 목록, Project 목록, `/api/contents/featured`의 최신 대표 콘텐츠를 함께 불러온다.
- 관리형 목록은 기존 정적 콘텐츠 fallback과 slug 기준으로 병합한다.
- API에서 받은 featured 콘텐츠가 있으면 이를 `Recent Updated`의 단일 데이터 원천으로 사용한다.
- API를 사용할 수 없는 정적 미리보기 환경에서는 기존 날짜 기반 Recent 계산을 fallback으로 유지한다.
- Recent 카드는 전시 종료일이 지나도 숨기지 않는다. 다음 콘텐츠가 공개될 때까지 제목, 이미지, 메타 정보와 상세 링크를 유지한다.

## 모바일 홈 순서

- 데스크톱 레이아웃은 현재 구조를 유지한다.
- 폭 768px 이하에서는 홈의 grid area 순서를 `Recent Updated`, `Project/Show 목록`, `Calendar`로 변경한다.
- Calendar 내부 기능과 공개 `/rental` 신청 경로는 변경하지 않는다.

## 기존 콘텐츠 보정

- 현재 공개된 `<멸망 언박싱>`을 Show 유형으로 유지 또는 보정한다.
- 이 콘텐츠를 홈 Show 목록에 포함하고 최신 Recent 대표로 지정한다.
- 보정은 기존 상세 데이터와 에셋을 보존하며 노출 관련 필드만 변경한다.

## 오류 처리

- 목록 API가 성공하고 featured 요청만 실패하면 목록은 그대로 표시하고 날짜 기반 fallback Recent를 사용한다.
- Publish 검증이나 저장이 실패하면 기존 공개 스냅샷과 기존 Recent 대표를 유지하며 관리자에게 기존 오류 메시지를 보여준다.
- featured 응답이 비어 있으면 날짜 기반 fallback을 사용한다.

## 검증

- 서버 테스트: Publish가 노출 필드를 강제하고 이전 대표를 해제하는지 검증한다.
- 스토어 테스트: featured 응답이 날짜순보다 우선하고, 실패 시 fallback이 유지되는지 검증한다.
- 어드민 테스트: Show/Project 선택 컨트롤이 있고 수동 노출 체크박스가 제거됐는지 검증한다.
- 홈 테스트: 종료된 Recent도 계속 노출되고 모바일 grid 순서가 `center → right → left`인지 검증한다.
- 브라우저 검증: 데스크톱 홈, 모바일 홈, 관리자 유형 선택과 Publish 흐름을 확인한다.
- 운영 검증: `<멸망 언박싱>`이 Show 목록과 Recent에 나타나고 상세 링크가 정상인지 확인한다.
- 어드민 자체 QA: 새 Show와 새 Project 각각에 대해 생성, 한글 입력, 유형 선택, 포스터·프리뷰·갤러리 업로드, 자동 저장, 미리보기, Publish까지 수행한다.
- 노출 자체 QA: Publish 직후 선택 유형의 목록과 Recent에 같은 콘텐츠가 보이고 반대 유형 목록에는 나타나지 않는지 확인한다.
- 재공개 자체 QA: 이미 공개된 콘텐츠의 유형을 변경해 다시 Publish했을 때 이전 목록·상세 경로가 제거되고 새 목록·상세 경로만 남는지 확인한다.
- 반응형 자체 QA: 실제 모바일 viewport에서 Recent, Project/Show, Calendar 순서와 가로 넘침 여부를 확인한다.
- 실패 자체 QA: 필수 필드 또는 포스터가 없는 draft의 Publish가 차단되고 기존 공개 콘텐츠와 Recent가 유지되는지 확인한다.
