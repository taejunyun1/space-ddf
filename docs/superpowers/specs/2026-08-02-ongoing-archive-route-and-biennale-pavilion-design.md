# 진행 중 전시 지도·경로 추천·광주비엔날레 파빌리온 수집 설계

## 목표

지역 전시·상영 아카이브의 지도는 사용자가 지금 방문할 수 있는 장소에 집중한다. 목록은 전체 기록을 보존하되 지도에는 현재 진행 중인 기록만 표시한다. 길찾기는 지도 안에 복잡한 기능을 넣지 않고 별도의 경로 플래너 페이지로 분리한다. 플래너는 진행 중 전시장 목록과 현재 위치, 광주비엔날레전시관, 국립아시아문화전당(ACC)을 출발지로 한 길찾기에만 집중한다. 광주비엔날레 기간에는 공식 파빌리온 장소와 주소를 자동 수집해 동일한 지도와 경로 추천 흐름에 포함한다.

## 승인된 범위

- 지도에는 `ongoing` 기록만 표시한다.
- 예정·종료·상태 불명 기록은 목록과 검색 아카이브에 유지한다.
- 아카이브 지도의 `길찾기` 버튼은 독립 경로 플래너 `/archive-route`로 이동한다.
- 경로 플래너는 선택한 전시 ID를 `?to={id}`로 받아 목적지를 미리 선택한다.
- 경로 플래너의 최종 결과는 Google Maps 새 창에서 연다.
- 출발지는 `현재 위치`, `광주비엔날레전시관`, `ACC` 세 가지를 제공한다.
- 전시장 주변 정보는 버스 정류장·노선, 지하철역, 공영주차장 순으로 보여준다.
- 광주비엔날레 공식 사이트에서 파빌리온명, 공간, 주소, 운영 정보를 회차별로 수집한다.
- 광주비엔날레 크롤러는 저장된 전시 기간 안에서 회차당 한 번만 성공 실행한다.
- 한 주소에 여러 파빌리온이 있으면 목록 데이터는 각각 보존하고 지도 마커는 물리적 공간 단위로 묶는다.
- 실시간 버스 도착정보는 첫 릴리스 범위에서 제외하고 정류장명과 노선번호까지만 표시한다.

## 기존 구조와 변경점

현재 `RegionalArchiveView.vue`는 목록 필터 결과에서 `closed`만 제외해 지도 데이터를 만든다. 이 때문에 `upcoming`과 `unknown` 기록도 지도에 들어갈 수 있다. 이를 `status === 'ongoing'`으로 좁힌다. 목록에 전달되는 `filteredItems`는 바꾸지 않는다.

지도 선택 상태는 지도에 존재하는 기록만 대상으로 한다. 사용자가 목록에서 예정·종료 기록을 선택했을 때 임의의 다른 진행 중 전시 상세를 대신 보여주지 않는다. 해당 조건에서 지도는 진행 중 마커를 유지하되 선택 상세는 닫고, `이 기록은 현재 지도 표시 대상이 아닙니다`를 안내한다. 필터 결과에 진행 중 전시가 하나도 없으면 `현재 진행 중인 전시가 없습니다`를 표시한다.

## 진행 중 상태 판정

지도 노출의 1차 기준은 API가 반환하는 정규화 상태 `ongoing`이다. 일반 전시 크롤러는 시작일과 종료일을 기준으로 상태를 계산하고 매일 03:00 KST에 갱신한다. 광주비엔날레 파빌리온 크롤러는 아래의 회차당 1회 실행 규칙을 적용한다.

- `startDate <= 오늘 <= endDate`: `ongoing`
- `오늘 < startDate`: `upcoming`
- `endDate < 오늘`: `closed`
- 날짜가 없거나 판정할 수 없음: 지도에서 제외

비엔날레 파빌리온처럼 기간이 명확한 신규 수집원은 반드시 시작일과 종료일을 저장한다. 날짜 문자열은 `YYYY-MM-DD`, 날짜 경계는 `Asia/Seoul` 기준으로 처리한다.

## 지도와 경로 플래너 진입

마커를 선택하면 기존 상세 카드 하단에 `길찾기` 링크를 배치한다. 이 링크는 선택한 전시 ID를 유지해 `/archive-route?to={id}`로 이동한다. 지도 페이지는 전시 탐색, 필터, 현재 진행 중 위치 확인까지만 담당하고 출발지·이동수단·주변 교통정보 UI는 포함하지 않는다.

## 독립 경로 플래너 UX

새 라우트 `/archive-route`와 `ArchiveRouteView.vue`를 추가한다. 페이지의 단일 목적은 진행 중 전시를 목적지로 선택하고 가장 이해하기 쉬운 형태로 외부 길찾기를 여는 것이다.

데스크톱은 두 칼럼으로 구성한다.

- 왼쪽: 진행 중 전시장 검색, 지역 필터, 전시장·파빌리온 목록
- 오른쪽: 고정된 `오늘의 이동 경로` 패널

오른쪽 패널은 다음 순서로 구성한다.

1. 출발지 선택
   - 현재 위치
   - 광주비엔날레전시관
   - ACC
2. 선택된 목적지
3. 이동 방식
   - 추천
   - 대중교통
   - 자동차·주차
4. `주변 교통` 요약
   - 가장 가까운 버스 정류장과 대표 노선번호
   - 가장 가까운 지하철역
   - 가장 가까운 공영주차장
   - 정보가 없는 항목은 행 전체를 숨긴다.
5. `Google Maps에서 길찾기` 링크

목적지를 바꾸면 URL의 `to` 쿼리와 오른쪽 패널을 함께 갱신한다. 직접 `/archive-route`에 들어오면 진행 중 전시장 목록을 보여주고 첫 항목을 임의 선택하지 않는다. 사용자가 목적지를 고른 뒤에만 길찾기 링크를 활성화한다.

모바일에서는 선택된 목적지를 상단에 고정하고 전시장 목록을 세로로 보여준다. 출발지와 이동 방식은 화면 아래의 바텀시트에서 한 손으로 조작하며, 최종 길찾기 링크는 안전영역 위에 고정한다. 키보드 탐색, 화면 읽기 순서, `prefers-reduced-motion`을 지원한다.

### 시각 방향

기존 DDF의 전역 토큰과 컴포넌트 문법을 그대로 사용한다.

- Paper `#ffffff`
- Ink `#151515`
- Line `#1c1c1c`
- 진행 중 `#d64b2a`
- 광주 위치 `#138a5b`
- 라벨과 데이터에 기존 `D2Coding`
- 얇은 구분선, 직선형 패널, 상태 pill, 기존 focus 스타일

페이지의 고유 요소는 출발지와 목적지를 세로선으로 연결하는 `전시 이동표`다. 이는 장식용 타임라인이 아니라 실제 출발·도착 구조를 표현하며 선택이 바뀌면 장소명과 상태가 즉시 갱신된다. 나머지 화면에는 새로운 장식 체계를 추가하지 않는다.

출발지 선택:

- `현재 위치`: Google Maps URL의 `origin`을 생략한다. 사이트는 위치정보를 직접 요청하거나 저장하지 않는다.
- `광주비엔날레전시관`: `광주광역시 북구 비엔날레로 111`
- `ACC`: `광주광역시 동구 문화전당로 38`

이동 방식 선택:

- `추천`: `travelmode`를 생략해 Google Maps의 관련 이동수단 추천을 사용한다.
- `대중교통`: `travelmode=transit`
- `자동차·주차`: `travelmode=driving`; 인근 공영주차장 링크를 함께 제공한다.

길찾기 URL은 `https://www.google.com/maps/dir/?api=1` 형식을 사용한다. 목적지는 전시장명과 주소를 우선 사용하고 주소가 없으면 위도·경도를 사용한다. 목적지 정보가 없으면 버튼을 숨긴다. 새 창 링크에는 `target="_blank"`와 `rel="noopener noreferrer"`를 적용한다.

현재 운영 보안 헤더의 `geolocation=()`은 유지한다. 현재 위치 판정은 Google Maps가 담당하므로 Space DDF 사이트가 위치 권한을 요구하지 않는다.

### Google Maps 요청·비용 최소화

경로 플래너 페이지에서는 Google Maps JavaScript API, Directions API, Routes API를 로드하거나 호출하지 않는다. 전시장 목록, 주소, 좌표는 기존 아카이브 API와 D1 데이터를 사용하고 주변 교통정보는 Worker 캐시를 사용한다. Google 서비스는 사용자가 최종 길찾기 링크를 직접 눌렀을 때 새 창의 Maps URL로만 열린다.

첫 릴리스에는 페이지 내 지도 미리보기를 넣지 않는다. 추후 필요성이 확인되면 사용자가 `지도 미리보기`를 명시적으로 누른 뒤에만 Google Maps JavaScript를 지연 로딩하는 별도 단계로 검토한다. 페이지 진입만으로 Google 지도 요청이 생기면 안 된다.

## 주변 교통정보

주변 정보는 경로 플래너에서 선택한 목적지 좌표를 중심으로 직선거리를 계산해 가까운 순으로 정렬한다. 패널이 과밀해지지 않도록 각 유형의 상위 결과만 표시한다.

- 버스: 가장 가까운 정류장 최대 2개, 각 정류장의 대표 노선 최대 5개
- 지하철: 가장 가까운 역 1개
- 공영주차장: 가장 가까운 공영주차장 최대 2개

데이터 출처 우선순위:

1. 버스 정류장·노선: 광주 BIS 공공 API
2. 지하철역: 검증된 광주 도시철도 역 데이터 스냅샷 또는 공식 공공데이터
3. 공영주차장: 광주 공영·민영주차장 공공데이터 중 `주차장구분=공영`인 기록
4. 데이터가 없거나 외부 API가 실패하면 해당 유형만 숨기고 길찾기는 정상 제공

공공 API 키는 브라우저에 노출하지 않고 Cloudflare Worker 환경변수에 저장한다. Worker가 외부 응답을 정규화하고 캐시한다. 정류장·역·주차장처럼 변화가 적은 데이터는 장기 캐시하며, 첫 릴리스에서는 실시간 도착 예정 시간을 요청하지 않는다. 필요한 서비스 키가 배포 시점에 준비되지 않았으면 주변 정보 섹션만 기능 플래그로 비활성화하고 핵심 지도·길찾기 기능은 배포할 수 있어야 한다.

## 광주비엔날레 파빌리온 크롤러

새 수집원 ID는 `gwangju-biennale-pavilion`으로 한다. 기존 Cloudflare Worker 예약 이벤트에서 실행 여부만 판정하되, 외부 공식 페이지를 매일 요청하지 않는다. 공식 한국어 페이지를 1차 출처로 사용하며 영어 페이지는 필드 누락 시 보조 출처로만 사용한다.

### 회차당 1회 실행 게이트

비엔날레 회차별 일정은 D1의 `biennale_editions`에 저장한다. 예약 이벤트가 실행될 때 Worker는 외부 네트워크 요청 전에 이 로컬 일정과 성공 기록만 확인한다.

- 오늘이 `startDate`보다 이르면 실행하지 않는다.
- 오늘이 `endDate`보다 늦으면 실행하지 않는다.
- 오늘이 전시 기간 안이고 `crawlCompletedAt`이 비어 있으면 파빌리온 크롤러를 한 번 실행한다.
- 수집과 저장이 모두 성공하면 `crawlCompletedAt`을 기록하고 같은 회차에서는 다시 실행하지 않는다.
- 실패하면 성공 완료 시각을 기록하지 않으며, 다음 예약 이벤트에서만 재시도한다.

따라서 정상 상황에서는 회차당 외부 크롤링이 정확히 한 번 발생한다. 매일 실행되는 것은 D1의 짧은 실행 여부 확인뿐이며 광주비엔날레 공식 사이트 요청은 발생하지 않는다. 운영자가 공식 변경사항을 반드시 다시 반영해야 할 때만 인증된 관리자 재실행으로 성공 상태를 초기화할 수 있다.

2026년 제16회 일정은 공식 본전시 기간인 `2026-09-05`부터 `2026-11-15`까지를 초기값으로 등록한다. 다음 회차는 배포 코드에 날짜를 하드코딩하지 않고 관리자 또는 D1 마이그레이션으로 회차와 기간을 먼저 등록한다.

수집 필드:

- 비엔날레 회차와 연도
- 파빌리온명 또는 참여 국가·기관
- 전시 공간명과 세부 공간명
- 도로명주소와 우편번호
- 시작일과 종료일
- 관람시간과 휴관일
- 공식 원문 URL과 공식 지도 URL
- 위도와 경도
- 수집 시각과 원본 payload

### 회차 가드

공식 사이트의 본전시 페이지와 파빌리온 페이지가 서로 다른 회차를 가리킬 수 있다. 2026년 8월 현재 본전시는 제16회 정보를 제공하지만 파빌리온 페이지 일부는 제15회 내용을 유지하고 있다. 따라서 다음 조건을 모두 만족할 때만 현재 회차 파빌리온을 신규 활성화한다.

- 파빌리온 페이지의 회차 또는 연도가 본전시 회차와 일치한다.
- 전시 기간이 본전시 기간 또는 공식 파빌리온 기간과 일치한다.
- 장소명과 주소가 한 쌍으로 파싱된다.

조건이 맞지 않으면 기존 공개 데이터를 덮어쓰지 않고 크롤링 실행 로그에 `edition_mismatch`로 기록한다.

### 주소와 좌표

공식 장소 페이지에 포함된 주소와 공식 지도 링크를 함께 저장한다. 네이버 지도 링크에 Web Mercator 좌표가 포함된 경우 이를 WGS84 위도·경도로 변환한다. 좌표가 없으면 정규화한 주소로 기존 장소 데이터와 대조한다. 자동으로 해소하지 못한 주소는 `needs_review`로 저장하고 공개 마커를 만들지 않는다.

주소 표기는 공식 한국어 주소를 우선한다. 영어 주소만 제공되면 원문을 보존하되 경로 목적지에는 공간명과 우편번호를 함께 전달해 모호성을 줄인다.

### 중복과 공간 묶음

각 파빌리온은 검색과 아카이빙을 위해 별도의 전시 기록으로 저장한다. 지도 그룹 키는 정규화 공간 ID와 좌표를 사용한다. 같은 ACC 주소처럼 여러 파빌리온이 한 공간을 공유하면 하나의 마커에 파빌리온 개수를 표시하고, 상세 카드에서 해당 공간의 파빌리온 목록을 펼친다.

중복 판정 키:

`edition + pavilion name + normalized venue + start date`

동일 크롤링에서 사라진 항목은 즉시 삭제하지 않는다. 연속 수집에서 반복 누락된 경우에만 비활성화해 공식 사이트의 일시적 오류가 공개 데이터를 지우지 않도록 한다.

## API와 데이터 모델

기존 전시 레코드 필드를 재사용하되 파빌리온 식별과 지도 검수를 위한 선택 필드를 추가한다.

- `edition`: `16`
- `editionYear`: `2026`
- `pavilionName`
- `venueGroupKey`
- `geocodeStatus`: `verified | needs_review`
- `crawlWarning`: `edition_mismatch | missing_address | missing_coordinates | null`

비엔날레 크롤러 실행 게이트는 회차별로 다음 상태를 저장한다.

- `edition`
- `editionYear`
- `startDate`
- `endDate`
- `crawlCompletedAt`
- `lastAttemptAt`
- `lastAttemptStatus`: `success | failed | null`
- `lastError`

주변 교통정보는 전시 레코드에 복제 저장하지 않는다. 목적지 좌표 기반 조회 API가 정규화 결과를 반환한다.

`GET /api/archive/nearby?lat={lat}&lng={lng}`

응답은 `busStops`, `subwayStations`, `publicParking` 배열을 포함하며 거리 오름차순으로 정렬한다. 외부 소스 하나가 실패해도 나머지 결과와 `warnings`를 반환한다.

## 오류 처리

- 지도 API 실패: 기존 지도 오류 안내 유지
- 진행 중 기록 없음: 빈 지도 위 상태 안내 표시
- 잘못된 `to` 값: 목적지를 선택하지 않은 기본 플래너 상태로 복구
- 길찾기 팝업 차단: 실제 `<a>` 링크를 사용해 사용자 클릭으로 새 창 열기
- 목적지 누락: 루트 버튼 숨김
- 주변 교통 API 실패: 해당 정보만 숨기고 길찾기 유지
- 비엔날레 회차 불일치: 신규 공개 중단, 기존 데이터 유지, 로그 기록
- 비엔날레 수집 실패: 완료 상태를 남기지 않고 다음 예약 이벤트에서 재시도
- 주소 검증 실패: 목록의 검수 상태로 보존하되 공개 지도에서 제외

## 보안과 개인정보

- Space DDF는 사용자의 현재 위치를 직접 수집·저장·전송하지 않는다.
- 공공데이터 서비스 키는 Worker secret으로만 저장한다.
- 외부 링크는 사용자 동작으로만 열고 `noopener noreferrer`를 적용한다.
- 크롤링 대상은 공식 공개 페이지로 제한하며 요청 간격, 출처 표시, robots 정책을 준수한다.

## QA 기준

자동 테스트:

- `ongoing`만 지도 데이터에 포함되고 전체 목록은 유지되는지
- 예정·종료 목록 선택 시 다른 전시가 지도 상세로 잘못 표시되지 않는지
- 지도 `길찾기` 링크가 선택 ID를 포함한 `/archive-route?to={id}`로 이동하는지
- 경로 플래너 목록에 진행 중 목적지만 표시되는지
- 잘못되거나 종료된 `to` 값이 임의의 다른 목적지를 선택하지 않는지
- 현재 위치 경로 URL에 `origin`이 없고 목적지가 올바르게 인코딩되는지
- 비엔날레·ACC 출발지 주소와 이동 방식이 올바르게 반영되는지
- 링크가 새 창과 안전한 `rel` 속성을 사용하는지
- 주변 정보가 거리순·개수 제한에 맞게 정렬되는지
- 동일 주소 파빌리온이 하나의 지도 그룹으로 묶이는지
- 전시 기간 전·후에는 비엔날레 외부 요청이 발생하지 않는지
- 전시 기간 중 첫 성공 이후 같은 회차에서 다시 요청하지 않는지
- 실패한 실행만 다음 예약 이벤트에서 재시도되는지
- 회차 불일치, 주소 누락, 좌표 누락이 공개되지 않는지
- 파빌리온 파서가 저장된 공식 HTML fixture에서 장소·주소·기간을 추출하는지
- 경로 플래너 진입 시 Google Maps JavaScript, Directions, Routes 요청이 없는지
- `/archive-route` 직접 요청과 새로고침이 Cloudflare Pages에서 정상 진입하는지

수동 QA:

- 데스크톱 2열과 모바일 바텀시트에서 경로 플래너를 자연스럽게 사용할 수 있는지
- 세 출발지와 세 이동 방식이 Google Maps 새 창에서 올바르게 열리는지
- 진행 중 전시가 없는 필터 상태의 안내가 명확한지
- 여러 파빌리온이 있는 마커의 목록과 길찾기 목적지가 올바른지
- 주변 버스·지하철·주차장 정보가 실제 장소와 일치하는지 표본 검증
- 운영 도메인에서 지도, 새 창, CSP, API 요청이 정상인지 확인
- 운영 도메인의 플래너 초기 진입 네트워크에 Google Maps API 요청이 없는지 확인

## 배포 순서

1. 지도 진행 중 필터와 선택 상태를 테스트 주도로 변경한다.
2. `/archive-route` 라우트, 독립 경로 플래너, Google Maps URL 생성기를 추가한다.
3. 파빌리온 파서·회차당 1회 실행 게이트·회차 가드·중복 묶음 테스트와 크롤러를 추가한다.
4. D1 마이그레이션과 Worker API를 배포한다.
5. 사용 가능한 공공데이터 키가 준비된 범위에서 주변 교통 API를 활성화한다.
6. 프론트엔드를 배포하고 운영 도메인에서 모바일·데스크톱 QA를 수행한다.

핵심 지도와 길찾기는 주변 교통 데이터 소스의 장애나 키 준비 여부와 분리한다. 이를 통해 현재 진행 중 전시만 표시하고 새 창 길찾기를 제공하는 기본 기능을 먼저 안정적으로 배포하면서, 주변 정보도 준비된 데이터부터 점진적으로 활성화할 수 있다.
